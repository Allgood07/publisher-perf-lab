# Publisher Perf Lab

Локальный стенд k6 для того же учебного сервиса, что и в [Publisher QA Lab](https://github.com/Allgood07/publisher-qa-lab). Сервис подключён как подмодуль на `ec1b5ce9fc45d7b2d33957957953f10a83c390a4`, не скопирован в этот репозиторий.

## Быстрый запуск

Нужны Git, Make и запущенный Docker. k6 и Node на машине устанавливать не нужно: образ закрепляет Node 22.22.0 и k6 1.0.0 по digest.

```sh
git clone --recurse-submodules https://github.com/Allgood07/publisher-perf-lab.git
cd publisher-perf-lab
make smoke
```

Если репозиторий уже склонирован, достаточно `git submodule update --init`. При первой сборке Docker скачает образы. Сам контейнер запускается с `--network none`, без опубликованных портов и с подмодулем только для чтения. Launcher запускает Publisher на динамическом порту loopback, передаёт этот порт k6 и завершает оба процесса при остановке. Контейнер удаляется после выхода. Параметра для указания другого сайта нет.

## Что проверяет smoke

1. Через штатные POST-запросы сохраняет и публикует V1.
2. Один виртуальный посетитель делает ровно пять чтений `/p/pilot-page`. Каждый ответ должен вернуть HTTP 200, точный заголовок и маркер V1 в HTML.
3. Любая ошибка HTTP, неверное содержимое или незавершённые итерации дают ненулевой код выхода. В GitHub Actions запускается та же команда `make smoke`.

Smoke проверяет, что стенд работает и отдаёт нужную версию. Его время отклика не является бенчмарком или SLA.

## Локальные замеры

`make measure-read` измеряет гостевое чтение; `make measure-publish` добавляет одного автора и отдельно измеряет, когда гость увидит новую версию после публикации. Это [базовая серия на 5 чтениях/с](reports/publisher-k6-e3da2e5.md).

`make measure-read-50` и `make measure-publish-50` запускают минутные измерения на 50 чтениях/с с теми же проверками содержимого. Перед ними можно пройти короткие ступени `make measure-probe-10`, `make measure-probe-25` и `make measure-probe-50`. [Отчёт о серии на 50 чтениях/с](reports/publisher-k6-50-979f9d9.md). Все профили работают только в изолированном контейнере, не на Site.pro и не на сторонних сайтах. GitHub Actions по-прежнему запускает только `make smoke`.

## Локальная проверка

На Docker Desktop 24.0.5 (`linux/arm64`) `make smoke` завершился успешно: 5/5 чтений, 10/10 проверок, 0 из 7 HTTP-запросов с ошибкой (ещё два запроса — подготовка V1). В отдельной контрольной сборке подменили только ожидаемый маркер: все пять ответов по-прежнему вернули HTTP 200, но проверка содержимого дала код 99. Без подмодуля контейнер завершился с ошибкой запуска; с зависшим процессом вместо k6 launcher остановил контейнер за 26 секунд. Это локальные прогоны, не результаты GitHub Actions.
